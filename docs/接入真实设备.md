# 接入真实设备

平台通过 MQTT 收数据。现场设备有两种接法：

- **能发 MQTT 的设备或网关**（边缘网关、IoT 模块、Node-RED、Kepware 等）：按下面的报文格式直接发到 MQTT 代理。
- **Modbus TCP 的 PLC / 仪表**：在 `config/platform.json` 里写好寄存器映射，由 `gateway/modbus_gateway.py` 轮询并转发。

所有配置都在 `config/platform.json`，改完重启服务生效。

## 1. 连接现场 MQTT 代理

```json
"mqtt": {
  "host": "192.168.1.10",
  "port": 8883,
  "username": "platform",
  "password": "",
  "tls": true,
  "ca_cert": "D:/certs/ca.pem"
}
```

密码不要写进配置文件，用环境变量传入：`MQTT_PASSWORD`（同样支持 `MQTT_HOST`、`MQTT_PORT`、`MQTT_USERNAME`、`MQTT_TLS`、`MQTT_CA_CERT`）。

连接失败或断线时后端会自动重试（1～30 秒退避），不需要手动重启。

使用现场代理（Mosquitto、EMQX 等）时，关掉内置代理和模拟器：

```json
"start": { "embedded_broker": false, "device_simulator": false, "modbus_simulator": false }
```

## 2. MQTT 报文格式

**单台设备**：主题 `industrial/device/<设备名>`

```json
{"value": 23.5, "unit": "°C", "type": "sensor", "timestamp": "2026-10-10T10:46:03Z"}
```

只有 `value` 是必填的。报文也可以直接是一个数字，例如 `23.5`。

**批量**：主题 `industrial/sensors/data`

```json
{"timestamp": "2026-10-10T18:46:03+08:00",
 "devices": {"TT-101": {"value": 23.5}, "PT-101": {"value": 1.2, "unit": "bar"}}}
```

规则：

- `value` 必须是数字或布尔值（布尔记为 0/1）。无效的值只丢弃那一台，同批其它设备照常入库。
- `timestamp` 可选，支持 ISO 时间（带时区会自动换算成本地时间）和 Unix 秒/毫秒。不填就用收到的时间。
- `unit`、`type` 不填时用配置文件中该设备的值。
- `status` 可选：`online` / `maintenance` / `offline`。
- 设备名不能包含 `/`，最长 100 个字符。新设备第一次上报时自动登记。

## 3. 设备、阈值和报警

```json
"devices": {
  "TT-101": {"type": "sensor", "unit": "°C", "alarm_min": 18, "alarm_max": 85}
}
```

- 超出 `alarm_min` / `alarm_max` 时设备状态变为 `warning`，并在**进入越限时**记一条报警，持续越限不会重复刷屏。
- 设备自带的 `"alarm": true` 也会触发报警。
- 超过 `offline_timeout_seconds`（默认 30 秒）没收到数据，设备标为 `offline`，并记一条 `device_offline` 报警。离线判断用的是平台收到数据的时间，不受设备时钟偏差影响。
- `retention_days` 大于 0 时，每小时清理一次超过该天数的历史数据。默认 0，表示不清理。

## 4. Modbus TCP 采集

```json
"modbus": {
  "enabled": true,
  "poll_interval_seconds": 2,
  "connections": {
    "plc1": {"host": "192.168.1.20", "port": 502, "unit": 1, "timeout": 3}
  }
},
"devices": {
  "TT-201": {"type": "sensor", "unit": "°C", "alarm_min": 0, "alarm_max": 90,
    "modbus": {"connection": "plc1", "table": "holding", "address": 100, "datatype": "float32", "word_order": "little"}},
  "FAN-01": {"type": "actuator", "unit": "RPM",
    "modbus": {"connection": "plc1", "table": "input", "address": 30, "datatype": "uint16",
               "write": {"table": "holding", "address": 0, "datatype": "uint16"}}},
  "LS-01": {"type": "io", "unit": "digital", "modbus": {"connection": "plc1", "table": "discrete", "address": 0}}
}
```

| 字段 | 说明 |
|---|---|
| `table` | `holding`（保持寄存器）、`input`（输入寄存器）、`coil`（线圈）、`discrete`（离散输入） |
| `address` | 从 0 开始的协议地址。PLC 手册写 40001 / 30001 时，减去 40001 / 30001 |
| `datatype` | `uint16`、`int16`、`uint32`、`int32`、`float32` |
| `word_order` | 32 位数据的字序，默认 `big`；读数明显不对时改成 `little` 试试 |
| `scale` / `offset` | 读数 = 原始值 × scale + offset；写入时自动反算 |
| `write` | 可选。配置后该设备可以在页面上下发设定值 |

`enabled: true` 时，`start_services.py` 会自动启动采集网关。单独运行的命令是 `python gateway/modbus_gateway.py`。PLC 断线后网关会在下个周期自动重连；某个地址读失败只影响那一个点位。

## 5. 设备控制

页面或接口 `POST /api/control/device` 发出的指令，会发布到 MQTT 主题 `industrial/control/<设备名>`：

```json
{"command": "set_value", "value": 1500, "timestamp": "..."}
```

配置了 `modbus.write` 的设备由采集网关写入 PLC；其它设备需要由现场网关订阅这个主题并执行。设备的实际值以之后上报的数据为准。MQTT 未连接时接口会返回失败，不会假装成功。

## 6. 接口访问令牌

在 `config/platform.json` 设置 `api_token`，或用环境变量 `API_TOKEN` 传入。设置后，除 `/api/health` 外的所有接口都要带请求头 `X-API-Token: <令牌>`（或 `Authorization: Bearer <令牌>`）。

前端在 `frontend/.env.local` 中写入同一个令牌：

```
VITE_API_TOKEN=<令牌>
```

注意：令牌会打包进前端代码，能打开页面的人就能看到它。它挡的是直接调用接口的请求，不能代替登录系统。对外开放前，还需要在反向代理上加登录或限制访问来源（`cors_origins` 也可以改成具体域名）。

## 7. 前端 3D 场景

`frontend/src/utils/plantLayout.js` 描述了 LINE-01 产线的布局，每个模型通过 `mqtt` 字段绑定设备名。换成现场设备时，把 `mqtt` 改成真实设备名。没有绑定到布局的设备，会在实时监控和设备管理里按通用设备显示。
